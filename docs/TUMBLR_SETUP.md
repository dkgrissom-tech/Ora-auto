## Why five secrets

Tumblr has no app-password or bearer-token path. It is OAuth 1.0a only, which
needs **two pairs**: the application's consumer key/secret, and the account's
token/secret. Both pairs are required to sign a single request.

| GitHub secret | What it is |
| --- | --- |
| `GRISSOM_TUMBLR_BLOG` | Blog identifier, full host — e.g. `grissompress.tumblr.com` |
| `GRISSOM_TUMBLR_CONSUMER_KEY` | App's OAuth consumer key |
| `GRISSOM_TUMBLR_CONSUMER_SECRET` | App's OAuth consumer secret |
| `GRISSOM_TUMBLR_OAUTH_TOKEN` | Account access token |
| `GRISSOM_TUMBLR_OAUTH_TOKEN_SECRET` | Account access token secret |

All five are already wired into the `env:` block of
`.github/workflows/auto_post.yml`, so adding them in repo Settings → Secrets is
the only step. No code change.

## Getting them

1. Register the app at <https://www.tumblr.com/oauth/apps> → "Register
   application". Callback URL can be `https://grissompress.pplx.app` — it is
   unused for this flow but the form requires one. This gives you the
   **consumer key and secret**.
2. Get the token pair from the API console at
   <https://api.tumblr.com/console/calls/user/info> — sign in, paste the
   consumer key/secret, authorize, and the console shows the resulting
   `token` and `token_secret`.

Unlike Threads, Tumblr OAuth 1.0a tokens do **not** expire on a 60-day clock,
so this is a one-time setup rather than another rotation to track before
September 8.

## Design notes

**Legacy `/post`, not NPF.** The legacy endpoint's `type=photo` accepts `source`
as a remote image URL, so images ride the same public `raw.githubusercontent`
path every other platform except Bluesky already uses. The newer NPF `/posts`
endpoint would require a multipart media upload for an identical result. Both
are documented at <https://www.tumblr.com/docs/en/api/v2>.

**The signature is hand-rolled.** `auto_post.yml` installs only
`requests atproto`. Adding an OAuth library would make every tick of every brand
depend on it, so `oauth1_header()` builds the HMAC-SHA1 signature from
`hmac`/`hashlib`. This is the same reasoning that keeps Pillow out of the
scheduler.

An almost-correct signature returns the same opaque `401` as an expired token,
so `tests/test_tumblr.py` pins the signature against a fixed vector generated by
`oauthlib` and verified byte-for-byte — including secrets containing `&`, `%20`
and `~`, the three characters a naive percent-encoder gets wrong. `oauthlib` is
not a dependency; only its output is.

**Tags matter more here than elsewhere.** Tumblr discovery is almost entirely
tag-driven, so the queue gained a `tags:` meta key (comma-separated). `booklr`
is the tag the Tumblr book community actually reads.

## Failure modes

| Log line | Meaning |
| --- | --- |
| `Tumblr not configured - missing GRISSOM_TUMBLR_...` | One or more of the five secrets is unset. Names the missing ones. |
| `401 ... the OAuth token or the signature was rejected` | Usually a revoked token. Re-mint via the API console. |
| `404 ... blog 'x' not found` | `GRISSOM_TUMBLR_BLOG` needs the full host, e.g. `name.tumblr.com`, not `name`. |
